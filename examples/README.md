# Examples

这些示例用于告诉学生“可以怎样直接开口”，也用于维护者检查 skill 的覆盖面。

## 常用提示

| 场景 | 文件 |
| --- | --- |
| 完整赛题推进 | `prompt_full_problem.md` |
| 只做某一问 | `prompt_single_question.md` |
| 根据代码和结果写论文 | `prompt_code_to_paper.md` |
| 生成技术路线图 | `prompt_roadmap.md` |
| 提交前评委视角终审 | `prompt_final_review.md` |

## 完整 Demo

`single_question_minimal/` 是最小单问输出示例，展示只做一问时不需要铺完整项目模板：

- 一个题面片段；
- 一个求解脚本；
- 一个核心结果表；
- 一张中文模型示意图；
- 一张中文结果图；
- 一个可放入论文的分问段落。

`full_problem_demo/` 是一个小型完整示例，包含：

- 题目；
- 原始数据；
- 任务计划；
- 求解代码；
- 结果表和图；
- 结果注册表；
- 验证报告；
- 论文片段。

这个 demo 不代表真实竞赛难度，它的作用是展示“可追溯、可检查、能写入论文”的交付形态。

## 真实案例

`real_cases/` 存放真实赛题材料。当前包含：

- `real_cases/cumcm_2025_a/`：2025 年国赛 A 题“烟幕干扰弹的投放策略”，包含题面 PDF、附件模板、题面解析、任务计划和附件审计。

真实案例用于检查 skill 在真实题面上的组织能力，不等同于标准答案。

## 更详细的使用场景

### 只做某一问

```text
[$cumcm-math-modeling] 只做第 1 问。请独立完成这一问：题意分析、变量定义、模型假设、公式、求解步骤、验证方法、结果表、中文图和论文段落。
```

如果没有真实数据，只给模型、求解思路和论文框架；如果有数据，才生成最终数值、图表和结果段落。

### 只写某一问论文

```text
[$cumcm-math-modeling] 请只写第 2 问论文部分。包括问题分析、模型建立、求解过程、结果解释、验证与敏感性分析、优缺点。没有来源的数字不要写。
```

论文写作应先读代码、结果表和图片，再写段落。

### 图太少时补图

```text
[$cumcm-math-modeling] 这一问图太少。请补充中文模型示意图、核心结果图，以及必要的验证/敏感性/约束检查图，并把图注写成论文可用版本。
```

只要题目里有几何关系、时间过程、空间布局、优化变量、评价指标、约束关系或流程关系，就应该优先画示意图。

### 最后两小时补救

```text
[$cumcm-math-modeling] 现在只剩最后两小时。请按优先级告诉我最该补什么，哪些问题会严重扣分，哪些可以先不做，怎样保证论文和结果不矛盾。
```

此时重点不是增加模型数量，而是保证每问有回答、关键结果可追踪、摘要正文一致、图表不乱引用。
