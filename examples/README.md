# Examples

这里放最常用的新手提问方式。你不用写很长的提示词，直接复制与你当前阶段最接近的一句即可。

## 最短可用提示

```text
[$cumcm-math-modeling] 帮我分析这道题。
```

```text
[$cumcm-math-modeling] 帮我求解第一问。
```

```text
[$cumcm-math-modeling] 帮我完成整道题。
```

```text
[$cumcm-math-modeling] 还有哪些模型可以考虑？
```

```text
[$cumcm-math-modeling] 可以直接推导公式吗？
```

```text
[$cumcm-math-modeling] 帮我建立更深的模型。
```

```text
[$cumcm-math-modeling] 帮我优化当前模型。
```

```text
[$cumcm-math-modeling] 帮我补验证和敏感性分析。
```

```text
[$cumcm-math-modeling] 帮我修改摘要。
```

```text
[$cumcm-math-modeling] 论文太浅，帮我改深一点。
```

```text
[$cumcm-math-modeling] 帮我检查能不能冲奖。
```

```text
[$cumcm-math-modeling] 快交了，帮我做最后检查。
```

这些短句会被自动补全。比如“帮我求解第一问”不会只写代码，而是默认包含：
读题、建模、公式推导、代码求解、结果表、图、验证、结果来源和 `paper/main.tex`。

## 按阶段选择

刚拿到题和附件：

```text
[$cumcm-math-modeling] 请先读题，拆解每一问，检查附件数据，并给出建模路线。
```

只做某一问：

```text
[$cumcm-math-modeling] 我只做第 1 问。请完成建模、求解、验证、图表和可写入论文的正文。
```

先把公式讲清楚：

```text
[$cumcm-math-modeling] 请从题意开始，一步步推导第 1 问的变量、假设、公式、约束和求解流程。
```

模型太简单：

```text
[$cumcm-math-modeling] 当前模型太浅。请检查缺了哪些机制、约束、基线和验证，并给出能落地的改进方案。
```

代码已经跑完，要写论文：

```text
[$cumcm-math-modeling] 请根据当前代码、结果表和图片写入 paper/main.tex，关键数字必须能找到来源。
```

论文图片和表格太多：

```text
[$cumcm-math-modeling] 论文现在图表太多、文字太少。请删减或降级不关键的图表，并把模型推导、结果解释和验证写深。
```

摘要最后重写：

```text
[$cumcm-math-modeling] 请最后重写摘要。摘要里的每个数字都必须和正文、结果表、图片、验证报告一致。
```

提交前检查：

```text
[$cumcm-math-modeling] 请从评委视角检查当前论文和材料，按严重程度列出会扣分的问题，并直接修复能修复的内容。
```

## 默认输出目录

| 目录或文件 | 放什么 |
| --- | --- |
| `problem/` | 题面、题意解析、每问任务拆解 |
| `data/` | 原始数据、清洗数据、预处理结果 |
| `modeling/` | 每问建模思路、公式推导、代码建模流程、验证计划 |
| `src/` | 数据处理、模型求解、绘图和验证代码 |
| `tables/` | 数据审计表、结果表、约束检查表、敏感性分析表 |
| `figures/` | 流程图、结果图、验证图 |
| `results/` | 验证报告、结果来源说明、最终校验记录 |
| `paper/main.tex` | 唯一论文入口文件 |

## 示例目录

| 目录或文件 | 用途 |
| --- | --- |
| `single_question_minimal/` | 只做一问时的最小输出示例。 |
| `full_problem_demo/` | 小型完整交付 demo，展示从题面到论文的全流程。 |
| `real_cases/cumcm_2025_a/` | 2025 年国赛 A 题 benchmark；不是标准答案。 |
| `real_cases/huadong_cup_a/` | 华东杯 A 题路线规划 benchmark；不是标准答案。 |

## 获奖注意事项

- 不要只追求“算出答案”。评委看的是建模逻辑、结果解释和验证证据。
- 每一问都要写清：为什么这样建模、变量从哪里来、公式怎么来、代码怎么求解、结果说明什么。
- 关键数字必须能追溯到题面、数据、代码输出、结果表、图片或验证报告。
- 优化题不能只说“最优”，要有可行性检查、求解状态或基线对比。
- 预测题不能只说“精度高”，要有误差指标和简单基线。
- 评价排序题不能只给排名，要说明指标方向、权重来源和排名稳定性。
- 图表要少而关键。图片和表格只用来支撑结论，不能替代文字推导。
- 论文正文要有深度，不要写成“建立模型、运行代码、得到结果”的短说明。
- 摘要最后写，摘要中的数字必须和正文、表格、图片、验证说明一致。
- 如果证据不够，就写清局限和风险，不要把普通结果包装成一等奖水平。
