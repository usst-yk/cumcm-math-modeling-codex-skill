# Examples

这里集中放使用者最常见的提问方式。新手不用记脚本名，直接复制下面的自然语言提示即可。

## 1. 刚拿到题

适合比赛开始、还没有确定路线时。

```text
[$cumcm-math-modeling] 这是我的赛题和附件。请先读题，拆解每一问，检查附件数据，然后给出建模路线。暂时不要直接写完整论文。
```

只做审题，不进入建模：

```text
[$cumcm-math-modeling] 请只做题面解析。列出每一问要解决什么、需要哪些数据、输出什么结果、有哪些约束、单位、时间范围、附件依赖和隐含评分点。
```

检查附件：

```text
[$cumcm-math-modeling] 请检查这些附件数据。重点看全部文件、Excel 全部 sheet、字段含义、缺失、异常、重复、单位、时间范围，以及每个附件可能对应哪一问。
```

## 2. 选择建模路线

适合队伍讨论阶段，先定主线。

```text
[$cumcm-math-modeling] 请给这道题设计 3 条建模路线。每条路线说明适用条件、模型结构、实现难度、风险、验证方式和论文表现力，最后推荐一条主路线。
```

如果是 A 题：

```text
[$cumcm-math-modeling] 这是国赛 A 题。请按工程物理类 A 题思路分析：先明确物理对象、坐标系、单位、状态变量、控制变量、约束和验证方式，再给出建模路线。
```

## 3. 只做某一问

适合队伍分工、只负责某一问，或者先把第一问做扎实。

```text
[$cumcm-math-modeling] 只做第 1 问。请独立完成这一问：题意分析、变量定义、模型假设、公式、求解步骤、验证方法、结果表、中文图和论文段落。
```

不想生成太多文件：

```text
只输出第 1 问需要的文件，不要生成完整项目模板。
```

只要最小输出参考，可以看：

```text
examples/single_question_minimal/
```

## 4. 写代码求解

适合模型方向已经确定，需要开始计算。

```text
[$cumcm-math-modeling] 请根据当前模型思路写第 1 问的求解代码。要求生成结果表、中文图和关键指标，并说明每个关键结果来自哪个文件。
```

如果是优化题：

```text
[$cumcm-math-modeling] 请写第 2 问优化求解代码。要求明确决策变量、目标函数和约束，保存推荐方案表、约束检查表、中文模型示意图、核心结果图和敏感性图。不要声称全局最优，除非有 solver status 或证明。
```

如果是预测题：

```text
[$cumcm-math-modeling] 请写预测模型代码。要求至少包含一个简单基线，保存预测结果表、误差指标表、预测曲线图和残差或验证图。
```

如果是评价排序题：

```text
[$cumcm-math-modeling] 请写评价排序代码。要求说明指标正负向，保存权重表、排序表、排名图，并做权重扰动或排序稳定性检查。
```

## 5. 图太少或图不清楚

适合已经有结果，但论文图不够解释模型。

```text
[$cumcm-math-modeling] 这一问图太少。请补充中文模型示意图、核心结果图，以及必要的验证/敏感性/约束检查图，并把图注写成论文可用版本。
```

只补题面或几何背景示意：

```text
[$cumcm-math-modeling] 请先画题面背景示意图。要求中文标题、坐标轴、图例和注释，突出对象位置、时间过程、约束关系或任务范围。
```

只补技术路线图：

```text
[$cumcm-math-modeling] 请根据当前建模方案生成技术路线图。要求适合放进数学建模论文，结构清楚、文字简洁、可编辑，并附图注。
```

## 6. 根据结果写论文

适合代码、表格和图片已经出来后。

```text
[$cumcm-math-modeling] 请根据当前代码、结果表和图片，写第 1 问论文部分。论文里的数字必须能在结果文件中找到来源。
```

只写某一问：

```text
[$cumcm-math-modeling] 请只写第 2 问论文部分。包括问题分析、模型建立、求解过程、结果解释、验证与敏感性分析、优缺点。没有来源的数字不要写。
```

从代码和图表整理成论文：

```text
[$cumcm-math-modeling] 请根据当前项目里的代码、结果表、图片和验证报告，把已经完成的子问题写成论文段落。先核对数字来源，再写正文和图注。
```

## 7. 验证和敏感性分析

适合已经算出结果，但不知道怎么证明可靠。

```text
[$cumcm-math-modeling] 我已经有了结果。请帮我做验证和敏感性分析：应该和什么基线比较，检查哪些约束，扰动哪些参数，论文里怎么写。
```

优化结果验证：

```text
[$cumcm-math-modeling] 请检查当前优化结果是否可靠。重点看 solver status、约束违反、基线方案比较、关键参数扰动和结果图表是否支撑结论。
```

预测结果验证：

```text
[$cumcm-math-modeling] 请检查当前预测结果是否可靠。重点看训练/验证划分、误差指标、残差图、基线比较和外推合理性。
```

## 8. 最终审稿和补救

提交前检查：

```text
[$cumcm-math-modeling] 请从评委视角检查当前论文和材料。重点看是否漏问、答偏题、数字不一致、图表不支撑结论、验证不足、假设没有用上。
```

最后两小时补救：

```text
[$cumcm-math-modeling] 现在只剩最后两小时。请按优先级告诉我最该补什么，哪些问题会严重扣分，哪些可以先不做，怎样保证论文和结果不矛盾。
```

团队分工：

```text
[$cumcm-math-modeling] 我们队有 3 个人。请根据这道题安排 72 小时分工：谁负责建模、谁负责代码、谁负责论文，每个阶段要交付什么，哪些结果必须同步。
```

## 9. 示例目录

| 目录或文件 | 用途 |
| --- | --- |
| `single_question_minimal/` | 只做一问时的最小输出示例。 |
| `full_problem_demo/` | 小型完整交付 demo，展示结果表、图、注册表、验证报告和论文片段。 |
| `real_cases/cumcm_2025_a/` | 2025 年国赛 A 题真实案例，不是标准答案。 |
| `README.md` | 所有自然语言提示集中在本文件，避免分散到多个小文件。 |

真实案例用于检查 skill 在真实题面上的组织能力，不等同于标准答案。
