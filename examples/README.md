# Examples

这里集中放最常用的提问方式。新手不用记脚本名，直接复制自然语言提示即可。

## 获奖最重要的注意事项

数学建模比赛最终交给评委看的不是代码、草稿或聊天记录，而是一篇
**能让评委快速读懂、相信、打分的论文**。模型决定上限，论文决定
这个上限能不能被看见。获奖最重要的是把**建模、结果、验证和摘要**
写成一篇完整、连贯、可复核的论文。

论文不是最后一天把各问结果粘在一起。每做完一问，都要同步准备：

- 这一问在整篇论文里的作用；
- 变量、假设、目标函数、约束和输出；
- 结果表、中文图、图注和正文解释；
- 基线、误差、约束检查、敏感性或边界情况；
- 和后一问共享的变量、参数、假设或评价指标。

建模也不是把算法堆得很复杂，而是找到一个**刚好可解**、能写清楚、
能验证、能支撑论文结论的好模型：

- 能抓住题目的核心数学关系；
- 变量、假设、目标函数、约束和输出都清楚；
- 假设合理、必要、可解释，不能为了可解而随便假设；
- 能用现有数据和比赛时间实现；
- 能算出结果、画出图、写进论文，并让评委看懂为什么可信；
- 能用基线、误差、约束检查、敏感性或边界情况验证。

摘要不是最后随便概括几句。好的摘要往往决定评委第一印象，但必须
最后写，因为它要和正文、图表、结果表、验证结论完全一致。摘要要逐问写清楚：

- 用了什么数学和建模方法；
- 得到了什么核心数值、排序、方案或结论；
- 怎么验证结果可靠；
- 模型有什么优点、局限或推广价值。

还要注意：数学建模的每一问通常不是孤立的。前一问的变量、假设、参数、数据清洗、评价指标或中间结果，常常会影响后一问。可以分工求解，但论文里的模型体系、符号、假设、图表和结论必须连起来。

国赛题通常不能靠暴力枚举硬算。好的建模应该把问题化简到“足够真实、足够可解、足够可验证”的程度。这里的关键是**合理假设**：假设要来自题意、数据、物理机制、业务逻辑或可说明的简化，既帮助问题变得可解，又不能改变题目的本质。模型太简单会答不准，模型太复杂会算不动、验不了、写不清；最好的模型往往是**靠合理假设抓住核心机制，又能稳定落地**。

## 1. 刚拿到题

适合比赛开始、还没有确定路线时。

```text
[$cumcm-math-modeling] 这是我的赛题和附件。请先读题，拆解每一问，检查附件数据，然后给出建模路线。暂时不要直接写完整论文。
```

只做审题，不进入建模：

```text
[$cumcm-math-modeling] 请只做题面解析。列出每一问要解决什么、需要哪些数据、输出什么结果、有哪些约束、单位、时间范围、附件依赖和隐含评分点。
```

只检查附件：

```text
[$cumcm-math-modeling] 请检查这些附件数据。重点看全部文件、Excel 全部 sheet、字段含义、缺失、异常、重复、单位、时间范围，以及每个附件可能对应哪一问。
```

## 2. 团队分工

适合刚读完题、准备三个人分头推进时。分工应该尽早做，不要等模型全定完才分。

```text
[$cumcm-math-modeling] 我们队有 3 个人。请根据这道题安排 72 小时分工：谁负责题意和建模，谁负责代码和数据，谁负责论文、图表和摘要；每个阶段要交付什么，哪些变量、假设、结果和论文口径必须同步。
```

如果只剩一天：

```text
[$cumcm-math-modeling] 我们只剩 24 小时。请按风险优先级重新安排分工：哪些问题必须先做，哪些模型可以简化，哪些图表和验证最值得补。
```

如果已经有人分到某一问：

```text
[$cumcm-math-modeling] 我负责第 2 问，队友负责其他问题。请告诉我第 2 问需要和其他问题同步哪些数据、变量、假设、参数、图表、结论和论文口径，避免每问孤立求解。
```

## 3. 选择建模路线

适合队伍讨论阶段，先定主线。

```text
[$cumcm-math-modeling] 请给这道题设计 3 条建模路线。每条路线说明核心数学关系、适用条件、模型结构、实现难度、风险、验证方式和论文表现力，最后推荐一条“刚好可解”的主路线。
```

如果是 A 题：

```text
[$cumcm-math-modeling] 这是国赛 A 题。请按工程物理类 A 题思路分析：先明确物理对象、坐标系、单位、状态变量、控制变量、约束和验证方式，再给出可实现、可验证、不过度复杂的建模路线。
```

想判断路线够不够强：

```text
[$cumcm-math-modeling] 请用评委视角评价当前建模路线，按题意覆盖、核心机制、基线、模型建立、验证、图表、结果追踪和论文可用性打分，指出最影响获奖层次的问题。
```

## 4. 深入建模思路

适合已经知道大方向，但还缺真正的数学模型。这里不要一次定稿，必须做 4 轮：先看核心机制，再写数学结构，再检查可解性、假设和验证，最后用评委视角挑错。没有完成第四轮，不要进入正式求解。

第一轮：抓核心机制。

```text
[$cumcm-math-modeling] 请先做第一轮建模思考，只抓问题的核心机制。不要急着定模型。请说明这个问题真正的数学关系是什么，输入是什么，输出是什么，哪些量可以控制，哪些量是约束，哪些量会连接不同子问。
```

第二轮：写数学结构。

```text
[$cumcm-math-modeling] 请做第二轮建模，把核心机制展开成数学结构。要求列出变量、参数、合理假设、符号表、核心公式、目标函数或评价函数、约束条件、基线模型和每问之间的变量/结果联系。
```

第三轮：检查是否刚好可解。

```text
[$cumcm-math-modeling] 请做第三轮建模审查。重点判断模型是否刚好可解：假设是否合理，公式是否能计算，数据是否支撑，约束是否能检查，是否避免暴力硬算，验证和敏感性分析怎么做。最后给出最推荐的模型版本。
```

第四轮：评委视角挑错。这一轮必须做。

```text
[$cumcm-math-modeling] 请用评委视角审查当前模型。重点找：假设不合理、变量定义不清、目标函数不对应题意、约束漏掉、每问割裂、验证不足、图表不能解释模型的问题，并给出修改后的模型表述。
```

一次性完整展开：

```text
[$cumcm-math-modeling] 请把当前建模路线展开成详细数学模型。要求包括：问题对象、变量和参数、必要且合理的假设、符号表、核心公式、目标函数或评价函数、约束条件、求解步骤、基线模型、验证方法、每问之间的变量和结果联系，以及为什么这些假设能让模型刚好可解、可实现、可写进论文。
```

每一问正式求解前，要求先保存建模思路：

```text
[$cumcm-math-modeling] 在写代码前，请先为每一问保存 modeling/qx_modeling_idea.md。每个文件都要写清本问作用、输入输出、假设、变量、核心公式、约束、基线模型、主模型、备选路线、求解计划、验证计划、图表计划和论文写法。后续代码必须按这个思路实现。
```

求解之后必须反过来检查一次。很多差论文的问题不是没有模型，
而是“论文写的是一个模型，代码实际算的是另一个模型”。所以每问出结果后，
都要让 Codex 用代码、结果表和图反向核对建模思路：

```text
[$cumcm-math-modeling] 第 1 问代码已经跑完。请反向核对代码实际使用的变量、公式、约束、算法、结果表和图片，判断它们是否和 modeling/q1_modeling_idea.md 一致。如果不一致，先修正最终建模思路，再把最终思路写进 paper/main.tex。
```

预测类建模：

```text
[$cumcm-math-modeling] 请详细建立预测模型。要求先给简单基线，再说明特征变量、时间范围、训练/验证划分、误差指标、预测公式或算法流程、外推风险，以及结果图和残差图应该怎么画。
```

优化类建模：

```text
[$cumcm-math-modeling] 请详细建立优化模型。要求明确决策变量、目标函数、约束条件、参数来源、可行域、基线方案、求解算法、solver status 或可行性检查、敏感性分析，以及论文里的模型建立部分怎么写。
```

评价排序类建模：

```text
[$cumcm-math-modeling] 请详细建立评价排序模型。要求列出指标体系、正负向处理、标准化公式、权重来源、综合得分公式、排序方法、权重扰动检验、排序稳定性，以及结果表和排名图怎么设计。
```

仿真/工程物理类建模：

```text
[$cumcm-math-modeling] 请详细建立仿真或工程物理模型。要求明确坐标系、状态变量、控制变量、单位、运动/变化方程、边界条件、约束判定、时间步长、数值误差、参数敏感性和示意图设计。
```

如果你觉得模型太空：

```text
[$cumcm-math-modeling] 当前方案太像套方法了。请重新从题目的实际机制出发，说明这个问题的核心数学关系是什么，哪些量是变量，哪些量是假设，哪些量是约束，哪些量是输出，哪些公式必须出现在论文里，并判断这些假设是否合理、模型是否刚好可解。
```

## 5. 只做某一问

适合队伍分工、只负责某一问，或者先把第一问做扎实。

```text
[$cumcm-math-modeling] 只做第 1 问。请独立完成这一问：题意分析、变量定义、模型假设、公式、求解步骤、验证方法、结果表、中文图和可直接放入论文的完整正文。论文正文不要只写结果说明，要写清为什么这样建模、公式怎么来、结果说明什么、验证说明什么，并保存为 paper/main.tex。
```

不想生成太多文件：

```text
[$cumcm-math-modeling] 只输出第 1 问需要的文件，不要生成完整项目模板。注意：精简文件不等于精简论文；如果写论文段落，仍要写成完整分问正文。
```

```text
[$cumcm-math-modeling] 我只需要第 1 问论文。请先核对已有结果表和图片，再写成 paper/main.tex。正文必须包括问题分析、假设和符号、模型公式、求解过程、结果解释、验证分析、局限说明和图表引用；不要编造新数字。
```

## 6. 写代码求解

适合模型方向已经确定，需要开始计算。

```text
[$cumcm-math-modeling] 请根据当前模型思路写第 1 问的求解代码。要求生成结果表、中文图和关键指标，并说明每个关键结果来自哪个文件。
```

优化题：

```text
[$cumcm-math-modeling] 请写第 2 问优化求解代码。要求明确决策变量、目标函数和约束，保存推荐方案表、约束检查表、中文模型示意图、核心结果图和敏感性图。不要声称全局最优，除非有 solver status 或证明。
```

预测题：

```text
[$cumcm-math-modeling] 请写预测模型代码。要求至少包含一个简单基线，保存预测结果表、误差指标表、预测曲线图和残差或验证图。
```

评价排序题：

```text
[$cumcm-math-modeling] 请写评价排序代码。要求说明指标正负向，保存权重表、排序表、排名图，并做权重扰动或排序稳定性检查。
```

## 7. 补图和路线图

适合已经有结果，但论文图不够解释模型。

```text
[$cumcm-math-modeling] 这一问图太少。请补充中文模型示意图、核心结果图，以及必要的验证/敏感性/约束检查图，并把图注写成论文可用版本。
```

只补题面或几何背景示意：

```text
[$cumcm-math-modeling] 请先画题面背景示意图。要求中文标题、坐标轴、图例和注释，突出对象位置、时间过程、约束关系或任务范围。
```

只补技术路线图：

```text
[$cumcm-math-modeling] 请根据当前建模方案生成技术路线图。要求适合放进数学建模论文，结构清楚、节点文字清楚、可编辑，并附图注。
```

## 8. 根据结果写论文

适合代码、表格和图片已经出来后。
所有论文成品默认写成 TeX；完整论文和单问论文都只写
`paper/main.tex`。Markdown 只用于草稿说明和阅读指南。

```text
[$cumcm-math-modeling] 请根据当前代码、结果表和图片，写第 1 问论文并保存为 paper/main.tex。论文里的数字必须能在结果文件中找到来源；正文要完整，不要写成几句结果概括。
```

只写某一问：

```text
[$cumcm-math-modeling] 请只写第 2 问论文并保存为 paper/main.tex。包括问题分析、变量和假设、模型建立、公式推导、求解过程、结果解释、验证与敏感性分析、优缺点和图表引用。没有来源的数字不要写。
```

整理已完成的结果：

```text
[$cumcm-math-modeling] 请根据当前项目里的代码、结果表、图片和验证报告，把已经完成的子问题写成论文段落。先核对数字来源，再写正文和图注。
```

## 9. 整理论文口径

适合各问正文基本写完，但还没有统一模型体系、符号、假设、图表和结果口径时。

```text
[$cumcm-math-modeling] 请帮我整理论文口径。重点统一各问之间的变量、假设、参数、方法名称、图表编号、核心数值、结论表述和限制说明。不要写摘要，先保证正文和图表一致。
```

## 10. 验证和敏感性分析

适合已经算出结果，但不知道怎么证明可靠。

```text
[$cumcm-math-modeling] 我已经有了结果。请帮我做验证和敏感性分析：应该和什么基线比较，检查哪些约束，扰动哪些参数，论文里怎么写。
```

优化结果验证：

```text
[$cumcm-math-modeling] 请检查当前优化结果是否可靠。重点看 solver status、约束违反、基线方案比较、关键参数扰动和结果图表是否支撑结论。
```

预测结果验证：

```text
[$cumcm-math-modeling] 请检查当前预测结果是否可靠。重点看训练/验证划分、误差指标、残差图、基线比较和外推合理性。
```

评价排序验证：

```text
[$cumcm-math-modeling] 请检查当前评价排序是否可靠。重点看指标正负向、权重来源、排序稳定性、权重扰动和排名图表是否一致。
```

## 11. 最后写摘要

摘要是获奖论文最重要的部分之一，但它应该最后写。先完成各问模型、结果表、图片、验证和正文，再写摘要；否则最容易出现摘要数字、正文数字和图表不一致。

好的摘要通常要做到：

- 开头直接说明研究对象和每一问的解决思路；
- 每一问都给出模型方法和核心数值结论；
- 写出关键验证结果或可靠性说明；
- 不写空泛背景，不写没有来源的数字；
- 结尾点出模型优点、局限或推广价值。

写最终摘要：

```text
[$cumcm-math-modeling] 现在各问正文、结果表、图片和验证已经完成。请最后写摘要。摘要必须包含每问使用的数学和建模方法、核心数值结论、验证结果、每问之间的联系和模型优缺点，所有数字必须能追溯，并且要和正文、图表、结论一致。
```

检查已有摘要：

```text
[$cumcm-math-modeling] 请检查我的摘要是否像获奖论文摘要。重点看是否逐问回答、是否有核心数值、是否和正文图表一致、是否有空话、是否遗漏验证或模型优缺点。
```

## 12. 最终审稿和补救

提交前检查：

```text
[$cumcm-math-modeling] 请从评委视角检查当前论文和材料。重点看是否漏问、答偏题、数字不一致、图表不支撑结论、验证不足、假设没有用上。
```

最后两小时补救：

```text
[$cumcm-math-modeling] 现在只剩最后两小时。请按优先级告诉我最该补什么，哪些问题会严重扣分，哪些可以先不做，怎样保证论文和结果不矛盾。
```

## 13. 不推荐但可用：直接求解整篇论文

一般不推荐一口气让 skill 完成整道题并写完整论文。单问提示词效果更好，
是因为任务边界更清楚，能把题意、变量、假设、公式、代码、图表、验证和
论文段落做完整；整篇论文一次做时，最容易把每一问都压薄，出现模型不深入、
图表不足、验证缺失、摘要和正文数字不一致等问题。

如果确实时间很紧，或者只是想先得到一个从题面到论文的粗版本，可以这样问：

```text
[$cumcm-math-modeling] 请直接完成整道题的建模求解并写出完整论文初稿。要求先解析题目和附件，再给出各问建模路线；每一问都必须包含变量定义、模型假设、公式、求解步骤、结果表、中文图、验证方法和论文段落；所有核心数字必须来自题面、附件、代码输出或结果表，不能编造；最后总装为 TeX 论文，摘要最后写，并检查摘要、正文、图表和结果表是否一致。如果因为时间或信息不足导致某一问只能给近似或草稿，必须明确标注限制，不要假装已经得到最优解。
```

这个提示词只能作为应急入口。更稳的做法仍然是：先审题和附件，再逐问建模、
求解、验证、写段落，最后统一口径并写摘要。
