# 赛中工作模式

根据用户当前阶段选择模式，但所有模式都遵守同一条主线：
求解和论文写作最终必须回到 `paper/main.tex`。审题、路线比较、候选模型和
预求解推导可以先沉淀到 `problem/` 或 `modeling/`，但要说明后续会怎样进入论文。
不要把审题、建模、求解、验证和写作割裂成互不相连的文件；论文是最终主交付，
其他文件是证据和复现材料。
用户提示很短时，先按 `prompts/intent-map.md` 自动补全意图，不要求用户
复制长提示词。
默认按一等奖导向执行：每个 CUMCM 任务都读取
`references/first-prize-workflow.md`，并写清官方 benchmark 对照、机制亮点、
验证亮点、图表亮点、论文叙事贡献和冲奖风险。

## 目录

- 只做审题路线
- 写/求解某一问
- 写完整论文
- 重做 benchmark 或真实案例
- 根据已有代码写论文
- 根据已有论文查漏洞
- 最后 2 小时压缩检查

## 只做审题路线

适用：刚拿到题、还没有确定方向。

输出：

- 子问题拆解。
- 数据和变量清单。
- 题型判断。
- 2-3 条候选路线。
- 推荐主路线和备选路线。
- 前 12 小时任务分工。
- 可选论文写入计划：说明后续哪些内容会进入问题重述、问题分析、数据与约束、
  建模路线；除非用户要求写初稿，否则不强制修改 `paper/main.tex`。

不输出：虚构结果、未经验证的数值结论、空模板堆。

## 写/求解某一问

适用：用户说“求解第一问”“完成第 x 问”“写某一问”“只做某一问”等。

单问模式只限制无用模板和空文件，不降低题意分析、建模、求解、验证、
图表和论文写作饱满度。默认交付该问的可复现结果，并把完整单问正文写入
`paper/main.tex`。不要把“求解”误解成只给脚本、表格或聊天式答案。

输出：

- 当前问题分析。
- 模型假设和符号。
- `modeling/qx_modeling_idea.md` 中必须有“逐步建模推导”或等价章节，按
  `references/modeling-derivation-standard.md` 写清题面文字如何转成变量、
  机制、公式、约束、算法和验证；不能只列核心公式。
- 解析基线、合理近似模型或边界条件。
- 数值模型和求解流程。
- `paper/main.tex` 中的完整单问论文正文：问题作用、变量假设、公式、
  算法、结果解释、验证、局限和与后续问题的衔接。
- 中文模型流程图、结果图和论文图注；如果少于两张图，需要说明原因。
- 结果表、必要验证表和验证说明。

即使只做一问，论文入口也必须是 `paper/main.tex`；不要输出
`paper/sections/qx.tex` 或 Markdown 成品。

单问模式默认也按一等奖导向执行，但只扩展当前问题：写清本问的官方
benchmark 对照、机制亮点、验证亮点、图表亮点、论文叙事贡献和冲奖风险，
不要顺手展开未请求的后续问题。

## 写完整论文

适用：已有题目、模型、代码或结果，需要整合成论文。

开始前读取 `references/paper-assembly.md` 和 `agents/paper_assembler.md`。

输出：

- 摘要。
- 问题重述和问题分析。
- 假设、符号、数据预处理。
- 各问题模型建立、求解、检验。
- 模型评价与推广。
- 参考文献占位或真实来源。
- 附录代码说明。
- 可编译的 `paper/main.tex` 和 PDF（环境允许时）。

要求：

- 没有数据结果时只写可追溯的框架、推导和阻塞说明，不编造数值。
- 完整论文不能只是每问片段拼接；必须有全局问题重述、问题分析、
  模型假设、符号说明、数据审计、模型检验、模型评价和结论。
- 每问都要写清机制、数学表达、求解过程、结果解释和验证。
- 完整论文和单问论文最终入口都必须是 `paper/main.tex`；Markdown 只能
  作为草稿说明。

## 重做 benchmark 或真实案例

适用：用户明确要求“重新做”“从头跑”“删除旧结果”“按 examples 步骤重做”。

开始前读取 `references/benchmark-rebuild.md`。

要求：

- 先删除旧的 `figures/`、`tables/`、`results/`、`paper/` 生成产物。
- 保留题面、原始数据和必要脚本。
- 重新题面解析、任务计划、数据审计、路线比较、四轮建模、求解、验证。
- 重新写 TeX 论文，摘要最后写。
- 不允许基于旧论文小修。

## 根据已有代码写论文

适用：用户已有 Python/MATLAB 代码或输出结果。

流程：

1. 读取代码的输入、输出、模型和图表文件。
2. 追踪每个结论对应的代码变量或输出文件。
3. 将代码逻辑转写为模型建立和求解过程。
4. 根据输出图表写论文结果段和图注。
5. 标记无法从代码追溯的结论。
6. 保存或更新 `paper/main.tex`。

## 根据已有论文查漏洞

适用：用户已有论文草稿。

检查：

- 是否每问都有明确回答。
- 摘要是否有具体数值结论。
- 公式符号是否定义完整。
- 数据处理是否可复现。
- 图表是否支撑结论。
- 结论是否能追溯到模型或代码。
- 是否存在虚构引用、虚构结果或前后矛盾。

检查后直接给出问题清单；若用户要求修改，修改统一回写 `paper/main.tex`。

查漏洞默认按一等奖导向审查。必须读取
`references/first-prize-workflow.md`、`references/first-prize-rubric.md` 和
`references/official-benchmark.md`，并按核心机制、验证、追溯、论文可读性
四个关键项给出阻断结论。任一关键项缺失时，不得称为完整或一等奖水平。

## 最后 2 小时压缩检查

适用：临近提交。

只做高收益检查：

- 摘要补数值结论。
- 每问第一段说明模型和结果。
- 删除无关模型堆砌。
- 检查图表编号、公式编号和单位。
- 检查代码附录是否能对应正文图表。
- 检查参考文献格式和真实性。
- 生成最终待改清单，按严重程度排序。

所有修正都优先落到 `paper/main.tex`。
