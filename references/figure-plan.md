# Figure Plan

论文优先输出不等于少画图，也不等于少分析、少建模、少验证。对新手来说，
图是理解模型最快的材料；少的是空模板和内部日志，不是示意图。

## Default Figure Requirement

每个被求解的子问题，在开始写代码或论文前先做一个图表计划。图表计划
可以短，但必须覆盖模型机制、核心结果和必要验证。

默认至少生成：

1. `fig_qx_model_flow.png`：最终模型流程图，默认用 GPT-image 生成。生成前把
   中文提示、节点、箭头、图注和论文解释保存到
   `modeling/qx_model_flow_prompt.md` 或 `modeling/flowcharts/`。
2. `fig_qx_result.png`：核心结果图。

如果有验证、误差、约束或敏感性分析，再生成：

3. `fig_qx_validation.png` 或 `fig_qx_sensitivity.png`。

如果题面对象、几何关系、机理结构或约束系统仅靠流程图说不清楚，再补
`fig_qx_model_schematic.png`。流程图解释建模步骤，示意图解释对象
结构；二者可以同时存在。

对优化、预测、评价排序、调度、仿真这类需要证明可靠性的题目，第三张检查图通常不是可省项。只有当检查结果用 1 个很小的表格更清楚时，才可以不画，并说明原因。

只有在“紧凑表格明显比图更清楚”时才可以少画图，并在最终回复里说明为什么没画。

## Full Problem Figure Set

完整赛题通常需要：

- `fig_problem_overview.png`：题面对象、坐标系、数据流或任务范围示意。
- `fig_route_overview.png`：GPT-image 技术路线图或逐问流程图。
- 每个已求解子问题至少 2 张图：模型流程图 + 结果图。
- 关键验证或敏感性分析再加 1 张图。

这不会和“论文优先输出”冲突，因为这些图是论文需要的结果，不是空模板。

## Figure Types By Task

| Task type | First figure | Second figure | Optional check figure |
| --- | --- | --- | --- |
| 预测 | 建模流程图，必要时加数据时间线/变量关系图 | 预测曲线与基线对比 | 残差图、误差分布 |
| 优化 | 建模流程图，必要时加决策变量、约束示意图 | 方案结果图、成本/收益分解 | 约束违反检查、敏感性曲线 |
| 调度 | 建模流程图，必要时加时间线、资源流或网络示意图 | 甘特图、路径图、资源占用图 | 可行性/冲突检查图 |
| 评价排序 | 建模流程图，必要时加指标体系图 | 排名条形图、权重图 | 排名稳定性或权重扰动图 |
| 仿真 | 建模流程图，必要时加机制流程或状态转移图 | 关键状态随时间变化图 | 参数扰动图 |
| 几何/空间 | 建模流程图，必要时加坐标系、对象位置、轨迹示意图 | 距离、覆盖、路径或布局结果图 | 边界点/约束可行性图 |
| 分类/聚类 | 建模流程图，必要时加特征空间图 | 聚类/分类结果可视化 | 混淆矩阵或误判样例 |

## Chinese Figure Rules

- 图题、坐标轴、图例、注释默认中文。
- 字号按 `references/figure-standards.md`，源图字号要偏大，插入论文后接近正文。
- 长标签换行，不要缩成小字硬塞。
- 每张图必须能对应一句论文结论。
- GPT-image 图生成后必须检查中文文字、箭头方向、节点顺序和是否混入未使用方法。

## Skip Rules

不要因为“赶时间”跳过模型流程图或必要示意图。可以跳过的情况只有：

- 题目是纯符号推导，图会误导；
- 用户明确要求只口头讨论且不要保存文件；
- 表格比图更清楚，例如只有 3 个标量结果；
- 用户明确要求“不画图”。

跳过时要写一句原因。
