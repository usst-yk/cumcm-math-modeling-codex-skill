\begin{abstract}
摘要应在全部子问题完成建模、求解、验证和正文统一后最后撰写。
逐问交代“方法、关键数值、验证证据和局限”，所有关键数字必须来自
已保存的表格、图片、代码输出或验证说明。摘要不是背景介绍，也不是
方法名列表，而应让评委独立看出每一问的答案和可信证据。

\textbf{对于问题一，}
本文针对……，将题面中的……转化为……变量和……约束，建立……模型。
求解得到……关键数值或方案；通过……基线/误差/可行性/敏感性检验，
说明该结果……。其主要局限是……。

\textbf{对于问题二，}
在问题一……结果的基础上，本文以……为目标，以……为硬约束，构造
……优化/评价/预测/仿真模型，得到……方案或排序。与……基线相比，
……指标改善……；验证结果表明……。其主要局限是……。

\textbf{对于问题三，}
本文进一步考虑……情形，采用……模型刻画……机制，得到……结论。
通过……扰动、边界情形或稳定性检查，说明模型在……范围内可靠，
但在……方面仍依赖……假设。

综合来看，本文模型的主要优点是……；局限性在于……。

\keywords{数学建模\quad 模型名称\quad 优化/预测/评价\quad 灵敏度分析}
\end{abstract}

\section{问题重述}

\subsection{问题背景}

用自己的话概括题目背景，只保留会影响建模的对象、过程、数据和目标。

\subsection{问题要求}

\begin{enumerate}
  \item 问题一需要回答什么，输入是什么，输出是什么。
  \item 问题二如何继承问题一的变量、参数或结论。
  \item 问题三需要扩展、优化、验证或推广什么。
\end{enumerate}

\section{问题分析}

\subsection{总体建模思路}

先说明本题的核心矛盾、主要变量、约束来源和各问之间的递进关系。
好的国赛论文不要把每一问孤立处理，而要说明统一的建模主线。

\subsection{问题一分析}

说明问题一属于预测、优化、评价、仿真、几何分析或机制建模中的哪一类，
为什么选择该数学结构，以及它为后续问题提供什么结果。

\subsection{问题二分析}

说明问题二如何使用问题一的结果，新增了哪些决策变量、目标函数或约束条件。

\subsection{问题三分析}

说明问题三是对前两问的推广、验证、敏感性分析还是综合策略设计。

\section{模型假设}

假设必须合理、必要、可解释，并且不能直接替代待求结论。

\begin{enumerate}
  \item 假设一：说明该假设对应题目中的哪类缺失信息，以及为什么合理。
  \item 假设二：说明该假设如何使模型刚好可解，而不是过度简化。
  \item 假设三：说明该假设对结果可能造成的影响，并在后文验证或讨论。
\end{enumerate}

\section{数据审计与预处理}

说明附件、字段、单位、缺失值、异常值、重复记录、时间范围和预处理方法。
数据审计表和关键预处理结果应与代码输出一致。

\section{模型建立、求解与结果}

本节写作原则是先讲清模型逻辑，再放关键图表。每一问都应形成连续的文字
论证链：题面事实如何转成变量，变量如何进入机制关系，机制关系如何形成
公式、约束或判据，公式如何由算法和代码求解，结果数值如何回答题目，
验证如何支持结论，局限会影响哪些外推。图表只保留能支撑核心结论的部分，
不要用大量图片和表格替代推导、解释和讨论。

\subsection{问题一：模型建立、求解与检验}

\subsubsection{本问作用与建模路线}

说明问题一在整篇论文中的作用：它直接回答题目哪一项要求，继承哪些题面
数据或假设，并向后续问题提供哪些变量、参数、结果或策略。比较基线、
主模型和保底路线，解释为什么主模型既能刻画题目机制，又能在比赛时间内
求解和验证。

\subsubsection{变量、假设与约束}

把题面中的对象、时间、空间、单位、硬约束和输出要求逐条转化为变量、
参数、集合、边界条件或数据字段。说明本问使用的假设分别解决什么缺失
信息，为什么合理，以及可能带来什么局限。

\subsubsection{模型建立与逐步推导}

从题目机制、几何关系、统计关系、评价逻辑或优化目标出发，逐步推导核心
方程、目标函数、评价准则或判定规则。每个公式下方都要说明左端、右端、
变量单位和约束来源，不能只给最终公式。本节应写成连续推导段落，不要只
排列公式、表格或流程图。

\subsubsection{求解算法与复现设置}

说明输入文件、预处理步骤、主要循环或求解器、参数设置、随机种子、停止
条件、求解状态和失败处理。若代码实现与初始建模思路不同，应写明修改
原因并引用代码反向验证结果。

\subsubsection{结果分析与题目回答}

先用文字说明为什么需要展示该结果，再插入问题一的核心结果表和结果图。
每张图表之后必须解释：图表展示什么、关键数值或趋势是什么、它回答了题目
哪一句要求、与基线或直觉是否一致。若同一结论已有一张图能说明，不再堆叠
相似图片或大表。

\subsubsection{模型检验、局限与本问小结}

给出基线比较、误差指标、约束可行性、敏感性、稳定性或边界情况检查。
说明验证结果支持哪些结论，仍有哪些局限，并总结本问向后续问题传递的
结果。

\subsection{问题二：模型建立、求解与检验}

\subsubsection{本问作用与建模路线}

说明问题二如何继承问题一的变量、参数或结论，新增了哪些决策目标、
约束或评价对象。比较基线、主模型和保底路线，说明主模型的机制贡献、
论文表现力和冲奖风险。

\subsubsection{变量、假设与约束}

定义本问新增变量、参数、目标函数或评价函数，写清硬约束、软约束、边界
条件和异常情况。说明每条新增假设的必要性、影响和验证方式。

\subsubsection{模型建立与逐步推导}

从题面要求推导目标函数、约束体系、递推关系、评价准则或策略判定规则。
说明模型如何把局部条件聚合成最终方案、排序、预测或评价结果。本节必须
解释模型为什么有深度，不能只写方法名和最终结果。

\subsubsection{求解算法与复现设置}

说明算法输入、求解流程、参数设置、求解状态、随机种子和输出文件。若
使用启发式或近似算法，必须给出基线、松弛界、小规模精确解或可行性检查。

\subsubsection{结果分析与题目回答}

插入问题二结果表和结果图，并解释关键数值、方案差异、约束余量或排序
变化。结果段必须先解释图表含义，再给出题目要求的直接答案。正文保留
最关键图表，过程表、全量明细和重复图放入附录或保存文件。

\subsubsection{模型检验、局限与本问小结}

给出与题型匹配的验证：优化检查可行性和敏感性，预测检查误差，评价检查
排序稳定性，仿真检查边界和参数扰动。说明局限和对后续问题的影响。

\subsection{问题三：模型建立、求解与检验}

\subsubsection{本问作用与建模路线}

说明问题三是对前两问的推广、综合策略、稳定性验证还是新情形求解。写清
它如何复用前文假设、变量、参数、结果或策略，并说明本问的冲奖贡献。

\subsubsection{变量、假设与约束}

列出本问新增的状态变量、控制变量、评价指标、场景参数或不确定因素。
说明约束来源、边界条件和假设影响。

\subsubsection{模型建立与逐步推导}

从新情形或综合目标出发，推导模型结构、目标或评价准则、约束系统和输出
转换方式。若引入更深数学模型，写清为什么需要、参数如何得到、如何验证。
若没有引入更复杂模型，也要解释为什么简化模型足够支撑本问结论。

\subsubsection{求解算法与复现设置}

说明场景生成、参数扰动、求解器或仿真流程、停止条件、随机种子和输出
文件。记录失败分支或保底路线。

\subsubsection{结果分析与题目回答}

插入核心结果、对比图和验证图。解释每个结果的实际含义、与前两问结论的
关系、是否改变最终策略或结论。不要让本节变成“图 1、表 1、图 2、表 2”
的连续罗列；每个图表都必须进入文字论证。

\subsubsection{模型检验、局限与本问小结}

给出稳定性、敏感性、边界情况或鲁棒性检查，说明模型在哪些条件下可信，
在哪些条件下需要更多数据或更复杂模型。最后总结整道题的主结论。

如只求解某一问，保留该问相关内容并删除无关占位；仍然只使用
\verb|paper/main.tex|，不要拆分为 \verb|paper/sections/*.tex|。

\subsection{代码反向验证与最终建模思路}

求解完成后，必须说明代码实际采用的变量、公式、约束、算法、结果表和图表
是否与原始建模思路一致。若代码为了可解性、稳定性或数据限制修改了模型，
应写清修改原因，并把最终采用的建模思路写入正文。论文不得描述一个
代码没有实现的模型。

\section{模型检验与敏感性分析}

\subsection{可行性与边界检查}

检查约束是否满足、单位是否一致、边界情况是否合理。

\subsection{误差或稳定性检验}

预测类问题给出误差指标；优化类问题给出可行性、基线比较和关键约束余量；
评价类问题给出权重扰动或排序稳定性；仿真类问题给出参数敏感性。

\subsection{灵敏度分析}

围绕会改变核心结论的参数进行扰动，不要只做形式化描述。

\section{模型评价与推广}

\subsection{模型优点}

\begin{itemize}
  \item 数学结构能抓住题目核心机制，并且可在比赛时间内复现。
  \item 关键结果有数据、代码、图表和验证说明支撑。
\end{itemize}

\subsection{模型不足}

\begin{itemize}
  \item 说明假设、数据质量或模型近似可能带来的误差。
  \item 说明进一步改进时需要哪些额外数据或更复杂模型。
\end{itemize}

\section{结论}

按子问题总结最终答案。结论中的每个关键数字都应能回到表格、图片、代码输出或验证说明。
