\begin{abstract}
摘要应在全部子问题完成建模、求解、验证和正文统一后最后撰写。
建议逐问交代“数学模型或方法、核心结果、验证情况、与后续问题的关系”，
所有关键数字必须来自已保存的表格、图片、代码输出或验证说明。

\textbf{对于问题一，}
本文基于……建立……模型，得到……。

\textbf{对于问题二，}
在问题一结果的基础上，本文以……为目标，以……为约束，建立……模型，
得到……。

\textbf{对于问题三，}
本文进一步考虑……，采用……方法，得到……，并通过……验证模型稳定性。

综合来看，本文模型的主要优点是……；局限性在于……。

\keywords{数学建模\quad 模型名称\quad 优化/预测/评价\quad 灵敏度分析}
\end{abstract}

\section{问题重述}

\subsection{问题背景}

用自己的话概括题目背景，只保留会影响建模的对象、过程、数据和目标。

\subsection{问题要求}

\begin{enumerate}
  \item 问题一需要回答什么，输入是什么，输出是什么。
  \item 问题二如何继承问题一的变量、参数或结论。
  \item 问题三需要扩展、优化、验证或推广什么。
\end{enumerate}

\section{问题分析}

\subsection{总体建模思路}

先说明本题的核心矛盾、主要变量、约束来源和各问之间的递进关系。
好的国赛论文不要把每一问孤立处理，而要说明统一的建模主线。

\subsection{问题一分析}

说明问题一属于预测、优化、评价、仿真、几何分析或机制建模中的哪一类，
为什么选择该数学结构，以及它为后续问题提供什么结果。

\subsection{问题二分析}

说明问题二如何使用问题一的结果，新增了哪些决策变量、目标函数或约束条件。

\subsection{问题三分析}

说明问题三是对前两问的推广、验证、敏感性分析还是综合策略设计。

\section{模型假设}

假设必须合理、必要、可解释，并且不能直接替代待求结论。

\begin{enumerate}
  \item 假设一：说明该假设对应题目中的哪类缺失信息，以及为什么合理。
  \item 假设二：说明该假设如何使模型刚好可解，而不是过度简化。
  \item 假设三：说明该假设对结果可能造成的影响，并在后文验证或讨论。
\end{enumerate}

\section{模型建立、求解与结果}

\subsection{问题一：模型建立、求解与检验}

补充问题一的模型、公式、求解过程、结果图表和验证。

\subsection{问题二：模型建立、求解与检验}

补充问题二的模型、公式、求解过程、结果图表和验证。

\subsection{问题三：模型建立、求解与检验}

补充问题三的模型、公式、求解过程、结果图表和验证。

如只求解某一问，保留该问相关内容并删除无关占位；仍然只使用
\verb|paper/main.tex|，不要拆分为 \verb|paper/sections/*.tex|。

\subsection{代码反向验证与最终建模思路}

求解完成后，必须说明代码实际采用的变量、公式、约束、算法、结果表和图表
是否与原始建模思路一致。若代码为了可解性、稳定性或数据限制修改了模型，
应写清修改原因，并把最终采用的建模思路写入正文。论文不得描述一个
代码没有实现的模型。

\section{模型检验与敏感性分析}

\subsection{可行性与边界检查}

检查约束是否满足、单位是否一致、边界情况是否合理。

\subsection{误差或稳定性检验}

预测类问题给出误差指标；优化类问题给出可行性、基线比较和关键约束余量；
评价类问题给出权重扰动或排序稳定性；仿真类问题给出参数敏感性。

\subsection{灵敏度分析}

围绕会改变核心结论的参数进行扰动，不要只做形式化描述。

\section{模型评价与推广}

\subsection{模型优点}

\begin{itemize}
  \item 数学结构能抓住题目核心机制，并且可在比赛时间内复现。
  \item 关键结果有数据、代码、图表和验证说明支撑。
\end{itemize}

\subsection{模型不足}

\begin{itemize}
  \item 说明假设、数据质量或模型近似可能带来的误差。
  \item 说明进一步改进时需要哪些额外数据或更复杂模型。
\end{itemize}

\section{结论}

按子问题总结最终答案。结论中的每个关键数字都应能回到表格、图片、代码输出或验证说明。
