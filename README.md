# CUMCM Math Modeling Codex Skill

面向全国大学生数学建模竞赛（CUMCM）的 Codex skill。

它不是一个完整的 Web 系统，也不承诺自动生成获奖论文。它的目标更明确：帮助学生把数学建模过程做稳，尤其是读题、附件审计、建模路线、可复现求解、结果追踪、图表和论文一致性。

## 项目见解

数学建模竞赛里，AI 最容易出错的地方通常不是“不知道模型名”，而是：

- 没有读全题意，只解决了题目的一部分。
- 没有检查全部附件，尤其是 Excel 的全部 sheet。
- 摘要、正文、代码、表格和图里的数字对不上。
- 写了“最优”“精度较高”，但没有约束检查、误差指标或基线比较。
- 论文先写完，后面再补结果，最后导致逻辑和数据不一致。
- 技术路线图好看但不可编辑，文字、箭头和流程不可靠。

这个 skill 的设计就是压住这些风险。它会尽量先解析题面和附件，再逐问推进，最后检查论文和结果是否一致。

同时它默认不再铺满模板文件。对新手来说，求解时只输出当前真正需要的代码、结果表、图片和论文段落；完整项目模板只在你明确要求时生成。

注意：精简输出不是少画图。模板和空日志可以少，但模型示意图、结果图、验证图要尽量保留。单问求解通常至少会给“模型/题意示意图”和“核心结果图”。

## 安装

在 Codex 中直接说：

```text
请安装这个 skill：https://github.com/usst-yk/cumcm-math-modeling-codex-skill
```

安装后重启 Codex。

使用时建议显式调用：

```text
[$cumcm-math-modeling] 请先解析这道数学建模题，不要急着建模。
```

## 最推荐的使用方式

对新手来说，不需要记脚本名，也不需要理解内部目录。你只要把目标说清楚。

最稳的开局方式是：

```text
[$cumcm-math-modeling] 这是我的赛题和附件。请先读题，拆解每一问，检查附件数据，然后给出建模路线。暂时不要直接写完整论文。
```

如果你已经知道自己只负责某一问，可以直接说：

```text
[$cumcm-math-modeling] 我只负责第 2 问。请只围绕第 2 问完成题意分析、建模路线、变量公式、求解方案、验证方法和可放入论文的段落。
```

如果你不想生成太多文件，可以直接加一句：

```text
只输出第 2 问需要的文件，不要生成完整项目模板。
```

如果你已经有代码和结果，只想写论文，可以说：

```text
[$cumcm-math-modeling] 请根据当前代码、结果表和图片，写第 1 问论文部分。论文里的数字必须能在结果文件中找到来源。
```

## 使用指南

### 1. 从零开始做一题

适合刚拿到题，还不知道怎么分工、怎么建模。

```text
[$cumcm-math-modeling] 请完整推进这道数学建模题。先读题和检查附件，再逐问给出建模路线、求解计划、验证方法、图表需求和论文写作安排。
```

Codex 会优先做：

- 题面解析；
- 子问题切分；
- 附件和 Excel sheet 检查；
- 每问的输入、输出、决策对象和约束；
- 三条可选建模路线；
- 推荐一条更适合比赛时间的路线。

### 2. 只做题面解析

适合比赛刚开始，或者你想先确认有没有读偏题。

```text
[$cumcm-math-modeling] 请只做题面解析。请列出每一问要解决什么、需要哪些数据、输出什么结果、有哪些约束、单位、时间范围、附件依赖和隐含评分点。
```

这个阶段不应该急着写模型，更不应该直接给最终数字。

### 3. 检查附件数据

适合你已经拿到 Excel、CSV 或其他附件，但不知道哪些表有用。

```text
[$cumcm-math-modeling] 请检查这些附件数据。重点看全部文件、Excel 全部 sheet、字段含义、缺失、异常、重复、单位、时间范围，以及每个附件可能对应哪一问。
```

原则：有 Excel 就检查全部 sheet，不能只看第一个工作表。

### 4. 只设计建模路线

适合队伍还在讨论方案，或者你想先确定主线。

```text
[$cumcm-math-modeling] 请给这道题设计 3 条建模路线。每条路线说明适用条件、模型结构、实现难度、风险、验证方式和论文表现力，最后推荐一条主路线。
```

这里的“三条路线”通常是：

- 基线路线：简单、可解释、能保底；
- 主模型路线：论文主体；
- 备选路线：主模型失败时可切换。

### 5. 只做某一问

适合队伍分工、课程作业只要求某一问，或者你想先把第一问做扎实。

```text
[$cumcm-math-modeling] 只做第 1 问。请独立完成这一问：题意分析、变量定义、模型假设、公式、求解步骤、验证方法、结果表和论文段落。
```

如果没有真实数据，Codex 应只给模型和论文框架；如果有数据，才应该生成最终数值、图表和结果段落。

### 6. 只写某一问论文

适合你已经有模型、代码或结果，只想把它整理成论文。

```text
[$cumcm-math-modeling] 请只写第 2 问论文部分。包括问题分析、模型建立、求解过程、结果解释、验证与敏感性分析、优缺点。没有来源的数字不要写。
```

论文写作会优先保证：

- 数字来自结果表或注册表；
- 图表和文字互相对应；
- 摘要、正文、结论口径一致；
- 不写空泛的“模型效果较好”。

### 7. 国赛 A 题专项

近年 A 题通常偏工程物理、几何、运动、控制和优化。这个 skill 已经加入 2020-2025 年 A 题模式总结。

适合 A 题时可以直接说：

```text
[$cumcm-math-modeling] 这是国赛 A 题。请按 A 题工程物理类题目的思路分析：先明确物理对象、坐标系、单位、状态变量、控制变量、约束和验证方式，再给出建模路线。
```

A 题通常会优先考虑：

- 工程过程控制：炉温曲线、波浪能、动力学、功率优化；
- 几何光学与曲面设计：FAST、定日镜场、反射、曲面、布局；
- 轨迹覆盖与避碰优化：板凳龙、烟幕弹、运动轨迹、遮蔽区间、碰撞判断。

真实案例见：

```text
examples/real_cases/cumcm_2025_a/
```

### 8. 写代码求解

适合模型方向已经确定，需要开始计算。

```text
[$cumcm-math-modeling] 请根据当前模型思路写第 1 问的求解代码。要求生成结果表、图和关键指标，并说明每个关键结果来自哪个文件。
```

建议要求 Codex 同时做：

- 保存结果表；
- 保存中文模型示意图；
- 保存中文核心结果图；
- 如果有验证或敏感性分析，再保存验证图；
- 说明运行方式；
- 让关键数字能追溯到结果表；
- 不把临时聊天里的数字直接写进论文。

只要题目里有几何关系、时间过程、空间布局、优化变量、评价指标、约束关系或流程关系，就默认画中文示意图。图中标题、坐标轴、图例和注释默认用中文。少于两张图时，应说明为什么。

### 9. 验证和敏感性分析

适合已经算出结果，但不知道怎么证明可靠。

```text
[$cumcm-math-modeling] 我已经有了结果。请帮我做验证和敏感性分析：应该和什么基线比较，检查哪些约束，扰动哪些参数，论文里怎么写。
```

常见验证包括：

- 与基线模型比较；
- 约束违反检查；
- 误差指标；
- 参数扰动；
- 边界情况；
- 小规模手算或枚举验证。

### 10. 根据结果写论文

适合代码、表格和图片已经出来后。

```text
[$cumcm-math-modeling] 请根据当前结果表、图和结果注册表，把第 3 问写成论文段落。要求逻辑清楚，数字有来源，图表有解释。
```

这个阶段应先读结果文件，再写论文，不要先编文字再补数字。

### 11. 生成技术路线图

适合论文主体路线已经确定后。

```text
[$cumcm-math-modeling] 请根据当前建模方案生成技术路线图。要求适合放进数学建模论文，结构清楚、文字简洁、可编辑，并附图注。
```

默认优先生成 Mermaid、SVG 或 Graphviz 这类可编辑路线图，不优先用 AI 图片。

### 12. 最终审稿

适合论文接近完成，准备提交前。

```text
[$cumcm-math-modeling] 请从评委视角检查当前论文和材料。重点看是否漏问、答偏题、数字不一致、图表不支撑结论、验证不足、假设没有用上。
```

终审时应优先指出严重问题，而不是泛泛润色。

### 13. 最后两小时补救

适合时间不够，必须保底交付。

```text
[$cumcm-math-modeling] 现在只剩最后两小时。请按优先级告诉我最该补什么，哪些问题会严重扣分，哪些可以先不做，怎样保证论文和结果不矛盾。
```

此时重点不是“做更多模型”，而是保证：

- 每一问都有回答；
- 关键结果可追踪；
- 摘要和正文一致；
- 图表不乱引用；
- 明显错误先修掉。

### 14. 队伍分工

适合 2-3 人团队安排比赛节奏。

```text
[$cumcm-math-modeling] 我们队有 3 个人。请根据这道题安排 72 小时分工：谁负责建模、谁负责代码、谁负责论文，每个阶段要交付什么，哪些结果必须同步。
```

| 需求 | 可以直接这样说 |

| 刚拿到题 | `请先读题拆解，不要急着建模。` |
| 从头推进 | `请完整推进全题，但逐问做，先不要空写论文。` |
| 只做一问 | `只做第 1 问，给出模型、求解、验证和论文段落。` |
| 只写论文 | `根据已有结果写第 2 问论文部分，数字必须有来源。` |
| 检查附件 | `请检查全部附件，尤其是 Excel 全部 sheet。` |
| 不会选模型 | `请判断题型，并给出三条可选建模路线。` |
| 国赛 A 题 | `请按工程物理类 A 题思路分析。` |
| 写代码 | `请写求解代码，并保存结果表和图。` |
| 做验证 | `请设计基线比较、约束检查和敏感性分析。` |
| 做路线图 | `请生成可编辑技术路线图，并附论文图注。` |
| 提交前检查 | `请从评委视角做最终审稿。` |

## 默认会得到什么

默认精简输出，不会一次性生成所有模板。比如只做一问时，通常只需要：

```text
src/            当前问题的求解代码
tables/         当前问题的核心结果表
figures/        当前问题需要的中文示意图或结果图
paper/sections/ 只有要求写论文时才生成分问段落
```

对一个已经求解的子问题，`figures/` 通常至少包含两类图：

```text
fig_qx_model_schematic.png   模型、题意、变量或约束示意图
fig_qx_result.png            核心结果图
```

只有你明确说“初始化完整项目”“全题交付”“所有中间文件都保存下来”，才会生成完整目录、日志、结果注册表、验证报告和论文模板。

## 文件架构

```text
cumcm-math-modeling/
├── SKILL.md                  # Codex 读取的 skill 入口
├── README.md                 # 给用户看的安装和使用说明
├── agents/                   # 题面解析、建模、代码、写作、审稿等角色提示
├── assets/                   # 论文、附录等静态模板
├── examples/                 # 使用示例、轻量 demo、真实案例
├── evals/                    # 轻量测试题，用来防止能力退化
├── references/               # 按需读取的详细规则和方法库
├── scripts/                  # 后台辅助工具，一般由 Codex 调用
├── templates/                # 新建项目时使用的模板
└── .github/workflows/        # GitHub 自动检查
```

关键文件：

- `references/task-routing.md`：判断当前需求该走哪种流程。
- `references/cumcm-a-problem-patterns.md`：2020-2025 年国赛 A 题模式总结。
- `references/problem-routing.md`：不同题型的建模路线。
- `references/output-policy.md`：新手默认精简输出。
- `references/figure-plan.md`：默认图表计划。
- `references/method-cards.json`：结构化方法卡。
- `references/result-tracking.md`：论文数字如何追踪来源。
- `references/scoring-checklist.md`：提交前评分检查。
- `scripts/problem_parser.py`：题面解析。
- `scripts/data_profile.py`：附件数据审计。
- `scripts/validate_results.py`：结果和论文一致性检查。
- `scripts/make_roadmap_svg.py`：可编辑技术路线图。

## 设计原则

- 先读题，再建模。
- 先检查数据，再写结论。
- 先基线模型，再复杂算法。
- 逐问推进，不先空写整篇论文。
- 每个关键数字都要能追踪到来源。
- 图表必须支撑一个具体结论；每个求解子问题默认至少画模型示意图和结果图。
- 数学建模论文中的图默认使用中文标题、坐标轴、图例、注释和图注。
- 技术路线图优先可编辑，不优先生成不可改的图片。
- 验证失败或输入不足时，明确写出阻塞项，不硬编结果。

## 边界

- 不保证获奖。
- 不替代人工确认关键假设。
- 不编造缺失数据、指标、排名、距离、参考文献或最优值。
- 不自动提交竞赛材料。
- 不把 Codex skill 变成完整 Web 应用或后端 Agent 系统。

## 维护者自检

普通学生不需要运行这些命令。维护 skill 时可以运行：

```text
python3 scripts/run_skill_evals.py
```

这个检查会覆盖题面解析、任务计划、demo 文件、方法卡和关键模板。仓库推送到 GitHub 后，也会自动运行同类检查。
