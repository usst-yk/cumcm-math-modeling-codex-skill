# CUMCM Math Modeling Codex Skill

面向全国大学生数学建模竞赛（CUMCM）的 Codex skill。它不是完整 Web/后端 Agent 系统，也不承诺自动生成获奖论文；它的定位是帮新手把数学建模过程理顺：先读题和检查附件，再确定建模路线，随后逐问求解、核对结果、整理图表和论文。

## 项目见解

数学建模竞赛里，AI 最容易出错的地方不是“不会写模型名”，而是：

- 没有读全题意和附件，只解决了一个相邻问题。
- Excel 多 sheet 没检查，数据覆盖不完整。
- 摘要、正文、表格、图和代码输出的数字不一致。
- 直接写“最优”“精度较高”，但没有可行性、误差或敏感性验证。
- 技术路线图好看但不可编辑，文字和箭头逻辑不可控。

这个 skill 的设计重点就是压住这些风险。使用时不需要了解内部工具和文件细节，只要用自然语言告诉 Codex 你要做什么，Codex 会在后台整理文件、检查数据、登记结果和做一致性检查。

## Codex 安装

在 Codex 中直接请求安装这个 GitHub 仓库：

```text
请安装这个 skill：https://github.com/usst-yk/cumcm-math-modeling-codex-skill
```

安装后重启 Codex。

使用时可以显式调用：

```text
[$cumcm-math-modeling] 请分析这道 CUMCM 题，先做题意拆解和建模路线设计。
```

## 使用指南

### 1. 开始新题

让 Codex 先建立一个标准工作区。后面的题面、附件、代码、图表、论文和检查记录都会放在固定位置。你只需要这样说：

```text
[$cumcm-math-modeling] 请为这道题新建一个项目，项目名为 2026A，后续所有材料都放在这个项目里。
```

这个操作只是整理工作区，不会替你编造模型或结果。它的作用是防止文件散乱、数字追踪断掉。

### 2. 刚拿到题，不知道怎么下手

适合比赛开始后的前几小时：

```text
[$cumcm-math-modeling] 我刚拿到这道题，还不知道怎么下手。请先帮我读题，拆解每一问要做什么、需要什么数据、最后应该交付什么结果。
```

### 3. 全题路线设计

适合比赛前期定方向：

```text
[$cumcm-math-modeling] 请给这道题设计整体建模路线。要求给出 3 种可选方案，说明每种方案的优缺点、实现难度、需要的数据和验证方式，最后推荐一条最稳妥的路线。
```

### 4. 分工和时间安排

适合队伍里有 2-3 个人时：

```text
[$cumcm-math-modeling] 我们队有 3 个人，请根据这道题帮我们安排 72 小时分工：谁负责建模、谁负责代码、谁负责论文，每个阶段应该完成什么。
```

### 5. 单问推进

适合只做某一问，避免全题发散：

```text
[$cumcm-math-modeling] 只做第 1 问。请先判断这问要回答什么、需要哪些数据、适合什么模型，再给出可执行的求解方案。没有真实计算结果时不要写最终数值结论。
```

### 6. 看不懂附件数据

适合已经有附件数据时：

```text
[$cumcm-math-modeling] 请检查我给的附件数据，看看有没有缺失、异常、重复、单位问题，以及 Excel 里每个工作表是否都被检查到。
```

### 7. 选择模型

适合你知道题意，但不知道该用什么模型时：

```text
[$cumcm-math-modeling] 这道题我看懂了，但不知道该选什么模型。请按预测、优化、评价、仿真等题型帮我判断，并给出适合新手实现的模型路线。
```

### 8. 方案太浅，想加深

适合已经有初稿，但感觉像普通作业时：

```text
[$cumcm-math-modeling] 这个方案太浅了。请帮我找出哪里缺少基线模型、约束条件、验证、敏感性分析或结果解释，并给出更像数学建模论文的改法。
```

### 9. 写代码求解

适合模型方向定了，准备开始计算时：

```text
[$cumcm-math-modeling] 请根据当前模型思路帮我写第 1 问的求解代码。要求代码能生成结果表和图，并说明每个关键结果来自哪里。
```

### 10. 代码报错或结果不对

适合代码跑不通、结果异常时：

```text
[$cumcm-math-modeling] 我的代码报错了，或者结果看起来不合理。请先帮我定位问题，不要直接改模型结论；如果结果不能信，请明确标出来。
```

### 11. 结果验证和敏感性分析

适合已经算出结果，但不知道怎么证明可靠时：

```text
[$cumcm-math-modeling] 我已经有了结果。请帮我设计验证和敏感性分析，说明应该和什么基线比较、看哪些误差或约束、哪些参数需要扰动。
```

### 12. 代码到论文

适合已有代码、表格和图后写论文：

```text
[$cumcm-math-modeling] 请根据当前已经算出的结果、表格和图片，把第 1 问写成论文段落。论文里的数字必须能找到来源。
```

### 13. 写摘要和结论

适合论文主体基本完成后：

```text
[$cumcm-math-modeling] 请根据当前论文和结果，帮我写摘要和结论。摘要要按每一问说明用了什么模型、得到什么结果、怎么验证，不能写空话。
```

### 14. 改论文语言

适合论文已经写完但表达不够像竞赛论文时：

```text
[$cumcm-math-modeling] 请帮我润色这段数学建模论文文字，让它更正式、更清楚，但不要改动没有数据支持的结论。
```

### 15. 做图表和图注

适合图有了但不知道放什么、怎么解释时：

```text
[$cumcm-math-modeling] 请帮我检查这些图表是否支撑论文结论，并为每张图写适合放进论文的图注。
```

### 16. 技术路线图

默认优先生成后续能修改的路线图，而不是一次性不可编辑图片：

```text
[$cumcm-math-modeling] 请根据当前建模方案生成技术路线图，要求结构清楚、文字不要太密，并附论文图注。
```

### 17. 提交前终审检查

适合提交前检查：

```text
[$cumcm-math-modeling] 请从评委视角检查当前论文和材料，重点看有没有答偏题、漏数据、数字前后不一致、图表不支撑结论、验证不充分的问题。
```

### 18. 最后两小时补救

适合时间不够，需要保底交付时：

```text
[$cumcm-math-modeling] 现在只剩最后两小时。请帮我按优先级列出最该补的内容：哪些问题会严重扣分，哪些可以先不做，怎样保证论文和结果不矛盾。
```

## 文件架构

```text
cumcm-math-modeling/
├── SKILL.md                  # skill 的核心说明
├── agents/                   # 不同工作阶段的角色提示
├── assets/                   # 论文和附录模板
├── examples/                 # 使用示例
├── evals/                    # 简单测试题
├── references/               # 更详细的建模规则
├── scripts/                  # 后台辅助工具，一般由 Codex 调用
└── templates/                # 项目模板
```

其中你通常只需要看 README 和使用指南。其他目录主要给 Codex 在后台使用。

Codex 会根据任务自动使用后台工具，例如整理项目、检查数据、记录关键结果、检查论文数字和图表是否一致。新手不需要手动运行这些工具。

## 设计原则

- 先审题和审计数据，再建模。
- 先基线和可解释结构，再复杂算法。
- 按子问题逐问推进，不先写整篇最终论文。
- 先保存代码产物，再写论文结论。
- 每个关键数值必须进入结果注册表。
- 技术路线图优先可编辑源文件。
- 验证失败或输入不足时，记录阻塞项，不硬写最终结论。

## 边界

- 不保证获奖。
- 不替代人工确认关键假设。
- 不编造缺失数据、参考文献、指标、距离、排名或最优值。
- 不自动提交竞赛材料。
- 不把 Codex skill 变成完整 Web 应用或后端 Agent 服务。
