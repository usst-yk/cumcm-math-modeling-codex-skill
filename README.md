# CUMCM Math Modeling Codex Skill

这是一个面向全国大学生数学建模竞赛（CUMCM）的 Codex skill。它不是自动获奖系统，也不是完整 Web 平台；它的目标是让学生更稳地完成：

读题、附件检查、逐问建模、代码求解、中文图表、验证分析和论文写作。

## 适合谁

- 刚拿到赛题，不知道从哪里开始。
- 队伍分工后，只负责某一问。
- 已经有代码或结果，需要写成论文。
- 图太少、验证不足、摘要和正文数字对不上。
- 提交前想按评委视角查错。

## 安装

在 Codex 中直接说：

```text
请安装这个 skill：https://github.com/usst-yk/cumcm-math-modeling-codex-skill
```

安装后重启 Codex。使用时建议显式调用：

```text
[$cumcm-math-modeling] 请先解析这道数学建模题，不要急着建模。
```

## 最推荐的用法

不要一口气要求：

```text
[$cumcm-math-modeling] 请直接求解整道题并写出完整论文。
```

这种用法通常质量很差：题意、假设、模型、代码、图表、验证和论文写作
会被压在一次回答里，容易出现模型没深入、结果不可追溯、图表太少、
摘要和正文不一致、每一问像独立小作文等问题。

更稳的方式是一步步推进：

```text
[$cumcm-math-modeling] 请先解析题目和附件，只做题意拆解、数据审计和每问输出要求，不要建模。
```

```text
[$cumcm-math-modeling] 请根据题意给出三条建模路线：基线方案、主方案和保底方案，并说明每条路线如何验证、如何写进论文。
```

```text
[$cumcm-math-modeling] 我们先做第 1 问。请完成变量、假设、公式、求解思路、验证方法、必要图表和论文段落。
```

```text
[$cumcm-math-modeling] 第 1 问结果已经完成。请检查结果是否可追溯，补验证和图表解释，然后再写第 1 问论文正文。
```

```text
[$cumcm-math-modeling] 请用代码输出反向核对第 1 问建模思路。如果代码实际采用的公式、约束或算法和原思路不同，先更新最终建模思路，再写进 paper/main.tex。
```

```text
[$cumcm-math-modeling] 各问结果、图表和验证都完成后，请总装完整论文，最后再写摘要，并检查摘要、正文、图表和结果表是否一致。
```

刚拿到题时：

```text
[$cumcm-math-modeling] 这是我的赛题和附件。请先读题，拆解每一问，检查附件数据，然后给出建模路线。暂时不要直接写完整论文。
```

只做某一问时：

```text
[$cumcm-math-modeling] 我只负责第 2 问。请只围绕第 2 问完成题意分析、建模路线、变量公式、求解方案、验证方法、必要图表和可放入论文的段落。
```

已经有结果，要写论文时：

```text
[$cumcm-math-modeling] 请根据当前代码、结果表和图片写论文段落。论文里的关键数字必须能在结果文件中找到来源。
```

需要完整论文或 benchmark 时，最终论文统一生成 TeX，入口文件是
`paper/main.tex`。Markdown 只作为草稿说明，不作为最终论文。

更多场景都放在：

```text
examples/README.md
```

## 默认原则

- 先读题，再建模；先检查数据，再写结论。
- 不建议一次性生成整篇论文。高质量论文要分阶段完成：解析题目、比较路线、
  分问建模、求解出图、验证结果、逐段写作、总装正文、最后写摘要。
- 论文质量优先于速度：完整论文必须把题意、假设、数学模型、求解、
  验证、图表解释和摘要写完整。
- 获奖导向下，论文是最终评审产品；代码、图表和结果表必须服务于论文
  的清晰表达、可追溯性和可信度。
- 论文成品和阶段性论文草稿统一使用 TeX，不用 Markdown 当最终论文。
- 默认论文优先输出：所有题意分析、建模过程、求解过程、验证过程、
  图表解释和结果结论都要回到 `paper/main.tex`。可以少建空模板和空日志，
  但不能省略主论文文件。
- 代码求解后必须反向核对建模思路。若代码实际实现的公式、约束、
  搜索策略或判据和原思路不同，先更新 `modeling/qx_modeling_idea.md`
  的最终思路，再写 `paper/main.tex`。
- 论文优先不等于少画图：每个已求解子问题通常至少有中文模型流程图和结果图，
  并在 `paper/main.tex` 中解释这些图支撑的结论；对象结构复杂时再补示意图。
- 论文图默认使用 skill 内置的 Noto Sans CJK SC 中文字体，避免 macOS 和
  Windows 字体差异导致中文显示难看；英文和数字优先 Times New Roman 风格。
- 优化、预测、评价、调度、仿真类问题，要补验证图、敏感性图或约束检查图。
- 关键数字必须能追溯到题面、数据、代码输出、结果表或结果注册表。
- 不承诺“一等奖”，但会用评委视角检查模型、验证、图表和论文一致性。

## 默认会生成什么

只做一问时，通常保留这些必要文件：

```text
problem/          题面原文、题意解析和任务拆解
data/             原始数据、清洗数据和预处理产物；不要用 date/
modeling/         每一问的详细建模思路、GPT-image 流程图提示和代码反向验证
src/              当前问题的数据处理、求解和绘图代码
tables/           当前问题的核心结果表、检查表和敏感性表
figures/          论文用中文图片，包括 GPT-image 流程图、结果图和验证图
results/          结果注册表和验证报告，追踪写入论文的关键数字
paper/main.tex    永远是论文入口；单问和全题都用这个文件
```

其中模型流程图和技术路线图默认用 GPT-image 生成：中文提示、节点、
箭头关系和图注放在 `modeling/` 或 `modeling/flowcharts/`，论文图片放在
`figures/`。

只有你明确说“完整项目”“全题交付”“初始化项目目录”或“所有中间文件都保存下来”，才会生成完整日志、全部 schema、完整审计表和附录模板。

如果目标是完整论文，建议明确说“完整项目”或“全题交付”，并按阶段推进。
这时保留必要中间文件是有价值的，例如题面解析、任务计划、数据审计、
分问建模思路、代码、结果表、中文图、结果注册表、验证报告
和最终 `paper/main.tex`。这些不是多余文件，而是保证论文可信和可复查的
工作痕迹。

## 文件夹怎么看

新手主要看这几个：

```text
README.md                         当前说明
examples/README.md                各种自然语言用法
examples/single_question_minimal/ 只做一问的最小输出示例
examples/full_problem_demo/       小型完整 demo
examples/real_cases/cumcm_2025_a/ 2025 年国赛 A 题真实案例
```

其他目录主要给 Codex 后台使用：

```text
SKILL.md       skill 入口
agents/        题面解析、建模、代码、写作、审稿角色提示
references/    细化规则、方法库、评分表和官方 benchmark
scripts/       辅助脚本
templates/     完整项目模式下的模板
evals/         质量检查和轻量测试
assets/fonts/  内置中文字体，保证跨系统图表字体一致
```

普通使用不需要手动打开这些后台目录。
